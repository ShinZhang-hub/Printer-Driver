# macOS 打印环境清理后程序失效 → 修复全过程记录

> 本文记录一次完整的排查链路：**运行"清理所有打印机和相关记录"脚本后，PrinterInstaller
> 装出的打印机无法打印，直到最终修复**。包含问题现象、根因、修复步骤与教训。
> 时间线：2026-08-14 18:39 → 19:16（约 40 分钟排查）。

## 背景

为了测试 PrinterInstaller，开发了 mac 端清理脚本 `Rebuild/scripts/reset-printers-mac.sh`，
意图把打印环境还原到"全新 Mac"状态。脚本共 10 步：

| 步骤 | 清理内容 |
|---|---|
| 1 | 停止打印服务（org.cups.cupsd） |
| 2 | 删除所有打印机队列（`lpadmin -x`） |

| 10 | 验证 |

脚本执行后，环境看似"全新"，但**重新用 PrinterInstaller 装打印机后无法打印**。

## 问题 1：过滤器文件缺失（No such file or directory）

### 现象

打印任务报错：

```
[Job 3] Unable to start filter "/Library/Printers/FUJIFILM/Filter/FFACMMCFilter"
        - No such file or directory.
[Job 3] Stopping job because the scheduler could not execute a filter.
```

### 根因

1. `Printer-Osaka` 的 PPD（`/etc/cups/ppd/Printer-Osaka.ppd`）引用了富士过滤器：
   ```
   *cupsFilter: "application/pdf 0 /Library/Printers/FUJIFILM/Filter/FFACMMCFilter"
   *APDialogExtension: ".../PDEs/FFACMMAccount.plugin"
   *APDialogExtension: ".../PDEs/FFACMMFeatures.plugin"
   ```
2. **reset 脚本第 7 步把 `/Library/Printers/FUJIFILM/` 整个目录删了**。
3. 但打印机队列（或后续重装）仍使用该 PPD → 过滤器找不到 → 打印失败。
4. 网络本身是通的（9100 端口可达），问题纯粹在本地驱动缺失。

### 关键点

- `printer-core` 内嵌的 `ff-mac-driver.ppd` **本身就引用** `/Library/Printers/FUJIFILM/...`，
  但**内嵌的是 PPD，不是过滤器二进制**。
- 过滤器 `FFACMMCFilter` 是富士官方驱动的一部分（从安装包
  `/Users/v_shinzhang/Desktop/MyInstaller/Payload/FUJIFILM/` 来），之前从未内嵌进程序。
- **架构**：过滤器是 Mach-O **x86_64** 二进制，本机是 arm64（Apple Silicon），
  依赖 **Rosetta 2** 才能跑（当前机器已装，故能打印）。

### 修复方案：内嵌驱动（参照 Windows）

与 Windows 端内嵌 INF 驱动包一致，把 PPD 引用的 3 个文件内嵌进 printer-core：

- `Filter/FFACMMCFilter`（124KB）
- `PDEs/FFACMMAccount.plugin`
- `PDEs/FFACMMFeatures.plugin`

实现（已提交 `f617279`）：
- `assets/drivers-macos/`：3 个 PPD 必需文件（2.8MB，最小编）
- `build.rs`：递归收集 mac 驱动 → `MAC_MANIFEST`（win 的 `MANIFEST` 保持不变）
- `src/mac_driver.rs`：`unpack_to()` 解包，保留相对布局
- `src/printer.rs`：安装时 Rust 解包到 /tmp → 管理员脚本 `ditto` 到
  `/Library/Printers/FUJIFILM`

### 手动恢复（应急）

```bash
sudo ditto "/Users/v_shinzhang/Desktop/MyInstaller/Payload/FUJIFILM" /Library/Printers/FUJIFILM
```

## 问题 2：过滤器权限不被 CUPS 接受（Invalid argument）

### 现象

恢复驱动后，打印仍失败，错误变为：

```
Printer-Osaka: 文件"/Library/Printers/FUJIFILM/Filter/FFACMMCFilter"有不安全权限（0100555/uid=501/gid=0）。
[Job] Unable to start filter ".../FFACMMCFilter" - Invalid argument.
```

### 根因

- CUPS 的过滤器以 **`_lp` 用户**运行，要求过滤器文件：
  - **owner 必须是 root（uid=0）**，不能是普通用户（如 uid=501）
  - 非 root 用户**不可写**
- **owner 澄清**：关键是"owner 是 root"而非必须是 `root:wheel`——`root:wheel` /
  `root:_lp` / `root:admin` 等任意 root 属组都可通过；**唯一不能换的是 owner 变成
  普通用户**（uid≠0），那会触发 CUPS 拒绝。`root:wheel` 是最标准、最稳妥的选择。
- 恢复时用 `ditto` 复制，**保留了源文件的 owner（v_shinzhang = uid=501）**。
- 权限 `0100555`（r-xr-xr-x）本身没问题，但 **uid=501 拥有** 触发 CUPS 的安全检查，
  直接拒绝执行。

### 修复

```bash
sudo chown -R root:wheel /Library/Printers/FUJIFILM
sudo chmod -R go-w /Library/Printers/FUJIFILM
sudo chmod 555 /Library/Printers/FUJIFILM/Filter/FFACMMCFilter
```

同时把修复写进程序（`printer.rs` 安装脚本，已提交）：
```bash
ditto "$DRV_SRC" /Library/Printers/FUJIFILM
chown -R root:wheel /Library/Printers/FUJIFILM
chmod -R go-w /Library/Printers/FUJIFILM
chmod 555 .../Filter/FFACMMCFilter
```

### 教训

- 用 `ditto`/`cp` 安装系统级文件时，**必须显式 chown**，不能依赖复制保留的 owner。
- CUPS 过滤器校验的是 **owner 身份**（root），不只是权限位。

## 问题 3：CUPS 缓存目录被删，作业卡住

### 现象

权限修复后，错误日志持续出现：

```
Unable to create "/private/var/spool/cups/cache/job.cache.N": No such file or directory
Unable to create KeepAlive/PID file ".../org.cups.cupsd": No such file or directory
```

作业排队但不处理（`lpstat -o` 一直有作业）。

### 根因

- reset 脚本第 5 步 `rm -rf /var/spool/cups/*` **把 `cache/` 子目录也删了**。
- cupsd 需要 `/var/spool/cups/cache/` 写 job.cache / PID 文件，目录没了就无法启动完整功能。

### 修复

```bash
sudo mkdir -p /private/var/spool/cups/cache
sudo chown _lp:_lp /private/var/spool/cups/cache
sudo chmod 755 /private/var/spool/cups/cache
sudo launchctl kickstart -k system/org.cups.cupsd
```

### 教训

- 清 `/var/spool/cups` 时**只清作业文件，不要删 `cache/` 子目录**（保留目录结构）。
- reset 脚本第 5 步应改为只删文件、保留 cache 目录。

## 问题 4：打印机被自动禁用（Filter failed）

### 现象

修复上述问题后，作业仍不执行，`lpstat -p` 显示：

```
Printer-Osaka 已停用，时间始于 ...
    Filter failed
```

### 根因

- 之前过滤器失败时，**cupsd 自动禁用了该打印机**（`cupsdisable`）。
- 即使底层问题已修复，打印机仍是禁用状态，作业不会跑。

### 修复

```bash
sudo cupsenable Printer-Osaka
```

### 教训

- 修复底层原因后，记得**重新启用打印机**（`cupsenable`）。

## Core 自愈方案（程序安装时自动修复极端环境）

被 reset 脚本"折磨"后的环境，mac 版本通过 `printer-core` 的安装脚本（root 执行）
自动修复。所有自愈逻辑集中在 `printer.rs` 的 mac `install_batch` 生成的 bash 脚本开头：

| # | 应对问题 | 自愈命令 |
|---|---|---|
| 1 | 驱动缺失（`No such file or directory`） | `ditto "$DRV_SRC" /Library/Printers/FUJIFILM`（从内嵌资源解包） |
| 2 | 过滤器权限被拒（uid=501） | `chown -R root:wheel` + `chmod -R go-w` + `chmod 555` |
| 3 | cache 目录被删（作业卡住） | `mkdir -p /private/var/spool/cups/cache` + `chown _lp:_lp` |
| 4 | 陈旧 Filter failed / paused | `launchctl kickstart -k system/org.cups.cupsd`（重启 cupsd 清状态） |
| 5 | 挂起作业阻塞 | `cancel -a -x` + `cancel -a` |
| 6 | 队列被禁用 | `install_one` 内 `cupsenable` |

**对正常（初始化）Mac 幂等无害**：cache 已存在、无作业、无队列 → 各命令空转，
不影响正常安装流程。

**关键洞察**：`cupsenable` 单独执行无法清除陈旧的 `Filter failed` 状态，
**必须重启 cupsd** 让 CUPS 重新加载队列/过滤器/状态后，作业才正常。这是第 4 步
`launchctl kickstart` 存在的原因。

## Reset 脚本的对应修复（已完成）

1. **步骤顺序调整**：`[1/10] 删队列` → `[2/10] 停服务`（原来先停服务导致 `lpadmin -x` 失效、队列残留，程序误判"已安装"）。
2. **spool 清理保留 cache**：`[5/10]` 改为 `find` 只清文件、保留 `/var/spool/cups/cache/` 目录结构。
3. 配合 core 自愈（上文），reset 制造极端环境后，重新安装打印机即可自动恢复。

> 补充：reset 删驱动后若队列残留，程序会因"队列存在"误判"已安装"而跳过安装。
> 这要求 reset 必须**先删队列再删驱动**（已通过步骤顺序保证）。
